# Корпоративная платформа товарных знаний на базе мультимодального GraphRAG

Выпускной проект курса OTUS «ИИ-архитектор».

Платформа интеллектуального доступа к товарным знаниям интернет-магазина коллекционных
масштабных моделей. Работает полностью в закрытом контуре, без обращений к внешним
LLM-API. Извлечение фактов выполняется обходом графа знаний, а не только векторным
поиском по тексту. Права доступа применяются на этапе выборки из хранилищ, поэтому
данные вне грифа пользователя физически не попадают в контекст модели.

- **Заказчик:** ООО «Скейлкар» (scalecar.ru) — свыше 15 000 позиций, ~400 марок, ~600 производителей моделей
- **Площадка пилота:** интернет-магазин 18-43.com
- **Статус:** проектирование, этап обследования

## Структура репозитория

```
├── infra/      docker-compose для поднятия всего стека (БД + приложения)
├── backend/    код агентов (Python) и API
└── docs/       архитектурная документация в Markdown и PDF
```

`infra/` и `backend/` наполняются по ходу курса. На текущем этапе проект существует
в виде проектной документации.

## Ключевые архитектурные ограничения

1. **Закрытый контур.** Обращения к OpenAI, Anthropic и другим внешним API исключены архитектурно.
2. **CPU-only на этапе разработки.** Тяжёлая мультимодальная обработка выносится в офлайн-конвейер,
   онлайн-путь остаётся лёгким. Требования к производительности разделены по профилям железа (NFR-1).
3. **Разграничение доступа до извлечения.** Фильтрация по меткам ACL выполняется в запросе
   к хранилищу, а не постобработкой ответа. Принцип fail-closed: неопределённый гриф — доступ запрещён.
4. **Агент как конечный автомат.** Линейные цепочки промптов не применяются.

## Режим обращения с данными

Репозиторий публичный. Реальные персональные данные, закупочные цены и тексты договоров
не размещаются здесь ни в каком виде, включая тестовые фикстуры и примеры в документации.
Подробнее — [раздел А.9](docs/02-data-sourcing-plan.md).
