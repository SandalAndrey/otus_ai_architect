# Диаграммы

Модель C4 описана кодом на [LikeC4](https://likec4.dev), а не нарисована:
элементы объявляются один раз, а уровни 1 и 2 строятся из одной модели. При
рисовании каждая диаграмма живёт отдельно, и переименование контейнера означает
правку во всех.

| Файл | Что это |
|---|---|
| `model.c4` | Модель: элементы, связи, представления |
| `L1-context.png` | Уровень 1, контекст |
| `L2-containers.png` | Уровень 2, контейнеры |

Обоснование выбора инструмента - [ADR-0003](../adr/0003-likec4-for-c4-model.md).

## Как посмотреть и поправить

Онлайн, без установки: <https://likec4.dev/playground/>, вставить `model.c4`.

Локально нужен Node.js:

```bash
npx likec4 start docs/diagrams      # интерактивный просмотр
npx likec4 validate docs/diagrams   # проверка модели
```

Для JetBrains есть плагин LikeC4, но он работает через LSP API и доступен только
в платных редакциях.

## Как пересобрать картинки

PNG - производные файлы: после правки модели их нужно пересобрать, иначе они
разойдутся с исходником.

Штатный экспорт рендерит ровно то, что видно в интерфейсе, но требует браузера
Playwright:

```bash
npx likec4 export png -o docs/diagrams docs/diagrams
```

Запасной путь через graphviz, если браузер недоступен:

```bash
npx likec4 gen dot -o dots docs/diagrams
dot -Tpng -Gbgcolor=white -Grankdir=LR -Gnodesep=0.35 -Granksep=1.2 \
    dots/index.dot -o docs/diagrams/L1-context.png
dot -Tpng -Gbgcolor=white -Grankdir=LR -Gnodesep=0.35 -Granksep=1.2 \
    dots/L2_Containers.dot -o docs/diagrams/L2-containers.png
```

Раскладку в этом случае считает graphviz, поэтому геометрия отличается от
интерфейса, содержание совпадает. Текущие картинки собраны этим способом.

Экспорт в drawio раскладку сохраняет, но перерисовывает сами элементы: фигуры
ролей ломаются, подписи связей наезжают друг на друга. Для документов он хуже.

## Что показано

**Уровень 1, контекст.** Пять ролей вместо одного обобщённого сотрудника:
покупатель, менеджер и закупщик различаются уровнем доступа, а эксперт-товаровед
и AI-инженер добавлены потому, что иначе их доступы в контур забываются при
проектировании безопасности.

Внешнего поставщика LLM на диаграмме нет, и это осознанно. В типовой схеме RAG
там стоит облачный провайдер; у нас закрытый контур, поэтому сервис инференса
находится внутри системы и появляется на уровне 2.

Покупатель обращается не к платформе напрямую, а к сайту, который встраивает
виджет и обязан передать роль пользователя. Так зависимость от чужой системы и
связанный с ней риск видны уже на верхнем уровне.

**Уровень 2, контейнеры.** Control Plane и Data Plane разделены явно и вложены
в границу платформы. Тяжёлая обработка документов вынесена в офлайн-конвейер: на
профиле железа без GPU она не укладывается в требования к латентности.

Нумерация связей 1-6 показывает путь запроса. Обращения к хранилищам идут с
фильтром по метке доступа, применяемым при выборке, а не после получения ответа.
