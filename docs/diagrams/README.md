# Диаграммы

Модель C4 описана кодом на [LikeC4](https://likec4.dev), а не нарисована:
элементы объявляются один раз, а все семь представлений строятся из одной
модели. При рисовании каждая диаграмма живёт отдельно, и переименование
контейнера означает правку во всех.

| Файл                | Что это                                      |
| ------------------- | -------------------------------------------- |
| `model.c4`          | Модель: элементы, связи, представления       |
| `L1-context.png`    | Уровень 1, контекст                          |
| `L2-containers.png` | Уровень 2, контейнеры                        |
| `L3-agent.png`      | Уровень 3, компоненты сервиса агента         |
| `Seq-answer-1.png`  | Сценарий 1а: приём запроса и извлечение      |
| `Seq-answer-2.png`  | Сценарий 1б: генерация ответа и доставка     |
| `Seq-answer-simple.png` | Сценарий 1в: простой вопрос, короткий путь   |
| `Seq-denied.png`    | Сценарий 2: запрос данных вне уровня доступа |

PNG - производные файлы: правится `model.c4`, картинки пересобираются.

Обоснование выбора инструмента - [ADR-0003](../adr/0003-likec4-for-c4-model.md).

## Как посмотреть и поправить

Онлайн, без установки: <https://likec4.dev/playground/>, вставить `model.c4`.

Локально нужен Node.js:

```bash
npx likec4 start docs/diagrams      # интерактивный просмотр
npx likec4 validate docs/diagrams   # проверка модели
```

## Как пересобрать картинки

PNG - производные файлы: после правки модели их нужно пересобрать, иначе они
разойдутся с исходником.

```bash
npx likec4 export png -o out --seq --light docs/diagrams
```

Флаг `--seq` включает последовательную раскладку для динамических представлений.
Без него они рисуются обычным графом, и порядок шагов теряется.

Экспорт в drawio сохраняет раскладку, но перерисовывает элементы: фигуры ролей
ломаются, подписи связей наезжают. Для документов хуже.

## Что показано

**Уровень 1, контекст.** Пять ролей вместо одного обобщённого сотрудника:
покупатель, менеджер и закупщик различаются уровнем доступа, а эксперт-товаровед
и AI-инженер добавлены потому, что иначе их доступы в контур забываются при
проектировании безопасности.

Внешнего поставщика LLM на диаграмме нет, и это осознанно. В типовой схеме RAG
там стоит облачный провайдер; у нас закрытый контур, поэтому сервис инференса
находится внутри системы и появляется на уровне 2.

Покупатель обращается не к платформе напрямую, а к сайту, который встраивает
виджет и обязан передать роль пользователя. Так зависимость от чужой системы и
связанный с ней риск видны уже на верхнем уровне.

**Уровень 2, контейнеры.** Control Plane и Data Plane разделены явно и вложены
в границу платформы. Тяжёлая обработка документов вынесена в офлайн-конвейер: на
профиле железа без GPU она не укладывается в требования к латентности.

Нумерация связей 1-6 показывает путь запроса. Обращения к хранилищам идут с
фильтром по метке доступа, применяемым при выборке, а не после получения ответа.

**Уровень 3, компоненты сервиса агента.** Раскрыт именно этот контейнер: он
лежит на пути пользовательского сценария, поэтому шаги диаграмм последовательности
ссылаются на его компоненты, а не на абстракции.

Оранжевым показаны агенты, синим - детерминированные компоненты. Различие не
оформительское: у агента поведение зависит от вывода модели, у компонента нет.
Поэтому guardrails, переранжировщик и запись аудита агентами не сделаны -
проверяемость guardrails на приёмке держится ровно на том, что их результат
воспроизводим. Обоснование состава - [ADR-0007](../adr/0007-multiagent-online-path.md).

**Сценарии.** Сценарий 1 разбит на две диаграммы. Причина не косметическая:
17 линий жизни в одной диаграмме нечитаемы, а граница между извлечением фактов и
генерацией ответа совпадает с фазами автомата.

Сценарий 1в показывает тот же вопрос, отнесённый супервизором к простому классу:
обход графа и сверка не выполняются, вызовов модели два вместо пяти. Он нужен
рядом с 1а и 1б, иначе адаптивная маршрутизация остаётся утверждением в ADR, а
на диаграммах виден только полный путь.

Сценарий 2 показывает отказ по правам: он выглядит как отсутствие данных,
поскольку фильтр по грифу отсекает узлы при выборке, а не после формирования
ответа.
