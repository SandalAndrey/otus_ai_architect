# 0001. Вести реестр архитектурных решений

- **Статус:** Принято
- **Дата:** 2026-08-12
- **Связанные требования:** раздел 8 БФТ (архитектурные риски), условие C-03 договора

## Контекст

Проект выполняется по модели T&M с ограничением стоимости. Потолок действует при
неизменном объёме работ, а изменение объёма оформляется отдельно и влияет на потолок.
Это означает, что стороны обязаны уметь отличать изменение, вызванное новым требованием,
от переделки, вызванной ошибкой проектирования.

Кроме того, значительная часть решений принимается в условиях неполной информации:
одиннадцать вопросов к Заказчику остаются открытыми, и часть решений придётся
пересматривать по мере поступления ответов.

## Решение

Каждое существенное архитектурное решение оформляется отдельной записью в `docs/adr/`
по шаблону `template.md`. Запись обязательно содержит контекст на момент принятия и
перечень рассмотренных альтернатив с причинами отклонения.

Записи неизменяемы: при пересмотре решения создаётся новая запись, старая получает
статус "Заменено" со ссылкой.

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| Описывать решения в общем документе HLD | Теряется история: видно текущее состояние, но не причины и не отвергнутые варианты |
| Фиксировать решения в задачах трекера | Привязка к инструменту, слабая связность, недоступно вне контура команды |
| Не фиксировать формально | Делает невозможным разделение ответственности за изменения по условию C-03 |

## Последствия

Появляется обязательная дисциплина: решение считается принятым только после появления
записи. Это замедляет принятие мелких решений, поэтому реестр ведётся только для
существенных - влияющих на структуру, стоимость или безопасность.
