# 0002. Применять разграничение доступа до извлечения

- **Статус:** Принято
- **Дата:** 2026-08-12
- **Связанные требования:** FR-3.1, FR-3.2, BR-01, NFR-3.1, риск R-06

## Контекст

Отсутствие утечки данных грифа Confidential - блокирующий критерий приёмки без права
смягчения. Требуется, чтобы один и тот же документ давал разный результат для разных
ролей: закупщик получает ответ со ссылкой на источник, менеджер и покупатель - отказ,
без раскрытия факта существования документа.

Распространённый способ реализации - отфильтровать запрещённое из уже сформированного
ответа модели. Он создаёт ложное ощущение безопасности: к моменту фильтрации данные
уже находились в контексте модели, а значит могли попасть в кэш, трассировку, логи
провайдера и в промежуточные рассуждения агента.

## Решение

Права доступа применяются как предикат в запросе к хранилищу: фильтр по меткам ACL
входит в Cypher-запрос к графовой базе и в payload-фильтр векторной базы. Узлы и чанки
вне грифа пользователя не извлекаются и, следовательно, не попадают в контекст модели.

Применяется принцип fail-closed: документ или узел с неопределённым грифом считается
конфиденциальным.

## Рассмотренные альтернативы

| Вариант                         | Почему отклонён                                                                                                             |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Постфильтрация ответа модели    | Данные уже попали в контекст, кэш и трассировку. Не проходит блокирующий критерий приёмки                                   |
| Отдельный индекс на каждый гриф | Дублирование данных, рассинхронизация при обновлении, кратный рост стоимости хранения. Не решает задачу пересекающихся прав |
| Проверка прав в промпте модели  | Соблюдение зависит от вероятностного поведения модели и обходится инъекцией. Недопустимо для безусловного обязательства     |

## Последствия

Векторная база выбирается с обязательной поддержкой pre-filter по метаданным без
деградации полноты выдачи - это проверяется на этапе обследования. Метка грифа
становится обязательным атрибутом при индексации, а конвейер загрузки обязан присвоить
её каждому чанку и узлу (FR-1.6).

Усложняется отладка: при отказе в ответе нужно различать отсутствие данных и отсутствие
прав. Для этого в аудит-журнал (FR-3.5) пишется перечень узлов, отсечённых фильтром.
