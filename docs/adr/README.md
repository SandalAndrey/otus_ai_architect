# Реестр архитектурных решений

Каждое существенное решение фиксируется отдельным файлом `NNNN-краткое-название.md`.
Записи не удаляются и не переписываются: устаревшее решение получает статус
"Заменено" со ссылкой на новое.

Необходимость реестра обусловлена в том числе контрактной моделью: при T&M с
ограничением стоимости требуется отличать изменение объёма работ, вызванное новым
требованием Заказчика, от переделки из-за ошибки проектирования. Без зафиксированного
контекста решения доказать это невозможно.

Статус "Предложено" у записи 0006 не оплошность. Выбор хранилищ упирается в
вопрос Q-16 о требованиях импортозамещения, который Заказчику ещё не задан, а
Neo4j в реестре отечественного ПО отсутствует. Запись утверждается на
работе 1.5 после ответа Заказчика.

Записи 0004, 0007 и 0009 содержат раздел "Соответствие и этика". Он обязателен
для решений, влияющих на поведение модели: галлюцинации, смещение выборки,
инъекции и токсичность, персональные данные, лицензии на веса, объяснимость.
Правило простое: на каждый пункт должен быть ответ в архитектуре - диаграмма
или требование. Если ответа нет, это не пробел в документе, а уязвимость
системы.
