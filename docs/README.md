## Связи между документами

```
БФТ (01) -- требования и NFR
  |
  +-- План работ (04) -- декомпозиция, критический путь
  |     |
  |     +-- Смета (06) -- часы по ролям и коэффициентам
  |           |
  |           +-- Реестр рисков (05) -- резерв в часах
  |           +-- Сайзинг и TCO (07) -- перевод в деньги
  |
  +-- Обоснование контракта (03) -- потолок и условия
        |
        +-- Change Request (08) -- инструмент пересмотра объёма

План обеспечения данными (02) -- источники и опросник, вход для всех
```

Цифры не дублируются между документами. Потолок считается в смете, обоснование
контракта на него ссылается. Риски оцениваются в реестре, смета берёт итог.

## Порядок работы

Проектная документация ведётся в Markdown и только в нём: PDF не читаются в diff
и расходятся с исходником при первой же правке. Если PDF нужен для отправки
Заказчику, он собирается локально и в репозиторий не попадает.

Исключение - каталог `homework/` за пределами `docs/`. Работы по курсу сдаются
преподавателю в формате PDF, поэтому там коммитятся и исходный Markdown, и
собранный из него файл. На документы в `docs/` это исключение не распространяется.

Диаграммы размещаются в [`diagrams/`](diagrams/) в формате Mermaid или PlantUML, чтобы
версионироваться как текст. Схемы C4, развёртывания, последовательности и модели
данных появятся здесь на этапе HLD.
