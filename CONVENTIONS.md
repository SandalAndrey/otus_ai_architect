# Соглашения проекта

## Символы в документации и коде

В файлах репозитория используются только основные символы, которые набираются
с клавиатуры. Правило распространяется на Markdown, Python, YAML, Cypher,
Dockerfile, Makefile и комментарии в коде.

| Вместо | Использовать | Пример |
|---|---|---|
| длинное и среднее тире, минус | дефис | `4-6 минут`, `Платформа - это ...` |
| ёлочки и кавычки-лапки | прямые кавычки | `ООО "Скейлкар"` |
| типографский апостроф | прямой апостроф | `don't` |
| многоточие одним знаком | три точки | `...` |
| стрелки | ASCII-стрелки | `->`, `<-`, `=>` |
| знаки сравнения | ASCII-запись | `<=`, `>=`, `!=` |
| знак умножения, плюс-минус | буква и связка | `x`, `+/-` |
| неразрывный и тонкий пробел | обычный пробел | |
| галочки и крестики в таблицах | слова | `да`, `нет` |
| греческие буквы в тексте | транслитерация | `sigma` |
| псевдографика в схемах каталогов | обычный список | |

Разрешены символы ASCII и кириллица. Всё остальное считается нарушением.

### Зачем

1. Типографские знаки не находятся поиском: `grep "T&M - "` не найдёт строку
   с длинным тире, и наоборот.
2. В git diff замена дефиса на тире выглядит как изменение строки, хотя смысл
   не поменялся. Это создаёт шум при ревью.
3. Разные терминалы, шрифты и IDE отображают их по-разному, а часть окружений
   без UTF-8 ломает их совсем.
4. Их нельзя набрать вручную при быстрой правке, поэтому текст неизбежно
   становится неоднородным.

### Проверка

```bash
python tools/check_punctuation.py        # проверить, код возврата 1 при находках
python tools/check_punctuation.py --fix  # заменить на месте
make check                               # то же через Makefile
```

Проверка выполняется перед коммитом. Скрипт сообщает не только об известных
символах из таблицы замен, но и о любом другом знаке вне ASCII и кириллицы,
поэтому новые случаи не пройдут молча.

## Документация

Документация ведётся в Markdown и только в нём. PDF в репозитории не хранятся:
они не читаются в diff и неизбежно расходятся с исходником. Если PDF нужен для
сдачи или отправки заказчику, он собирается локально и остаётся вне репозитория
(каталог `docs/pdf/` внесён в `.gitignore`).

Диаграммы размещаются в `docs/diagrams/` в формате Mermaid, чтобы они
версионировались как текст и были видны в diff.

## Архитектурные решения

Существенные решения оформляются записями в `docs/adr/` по шаблону
`docs/adr/template.md`. Записи неизменяемы: при пересмотре создаётся новая,
старая получает статус "Заменено" со ссылкой.

## Данные

Реальные персональные данные, закупочные цены и тексты договоров не попадают
в репозиторий ни в каком виде, включая тестовые фикстуры и примеры в
документации. Подробнее - `docs/02-data-sourcing-plan.md`, раздел А.9.
